# Cover letters and application answers

Write these only when the user asks. They use the same facts as the CV and the same rules: nothing invented, numbers as supplied, unverified items marked.

## The reason comes from the user

A cover letter and a "Why this role?" answer both need the user's real reason for wanting this job. Look for it in what they've already said. If it isn't there, ask one question, for example: "What made this one stand out from the other postings you've looked at?" Fitting the requirements is not a reason, and enthusiasm can't be written in on the user's behalf. If they have no specific reason, write a plain, honest letter about the work instead of inventing admiration for the company.

## Cover letter

Its job is to show why this person wants this work and why a conversation is worth having. The CV carries the evidence.

- Open with the concrete reason or connection. Not "I am writing to apply for...", and not a paraphrase of the company's mission.
- Use one example: the one closest to the job's main need, with its result. Add a second only if it answers a separate requirement.
- If one gap would otherwise stop the reader, address it directly: what's missing, the closest real experience, and how the user would close it.
- Say only what the posting or the user supports about the company. No invented diagnosis of its business.
- Don't retell the CV in paragraphs.
- End with a plain next step, not a slogan.
- Keep it well under a page unless the employer asks for more.

Then read it once as a hiring manager who has never met the user. After one read, can you say why they want this job and why to talk to them? If not, fix the opening before anything else.

## Application answers

- Copy each question and its word or character limit exactly, and stay inside the limit.
- Answer the question in the first sentence. "Why are you interested?" is not "Why are you qualified?".
- Use one example in enough detail to be believed, rather than a list.
- Read all the answers together in form order: no repeated story, no repeated opening, no framework pasted into every answer.
- If a sentence would fit a hundred other candidates after swapping the company name, cut it.
- When a question touches a gap, state it plainly. "I haven't run X; the closest I've done is Y" is stronger than a vague answer.
- For salary, notice period, work authorisation or availability, use only what the user states. Never guess.
