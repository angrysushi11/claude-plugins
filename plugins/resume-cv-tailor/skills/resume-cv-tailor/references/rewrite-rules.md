# Rewrite rules

## Bullets

One claim per bullet: what the user did, how, and the result or scope.

- Start with a specific verb for what the user actually did: built, wrote, negotiated, cut, hired, analysed, launched, ran.
- Put the result where a skim will catch it, with its baseline when the user has one: "from 22% to 27%" says more than "by 5 points".
- Keep the scope that makes a claim checkable: the market, the period, the team size, the budget. These are boundaries, not hedges.
- Recent, relevant roles get the most bullets. Old or unrelated roles get one line.

## Hedges and what replaces them

| Hedge | Replace with |
| --- | --- |
| helped with, assisted with, supported | the part the user did: "wrote the onboarding emails for the launch" |
| was involved in, participated in, contributed to | the user's own action, with the team result as context |
| responsible for | what they did in that role, and what changed |
| approximately, about, around, roughly | the exact figure, or a true bound: "over 20%" |
| various, several, multiple | the number, if the user has it; otherwise cut the word |

Confidence comes from precision. It never comes from upgrading ownership: "helped with the launch" does not become "led the launch" unless the user says they led it. When the real contribution is unclear, keep the plain version and put the question on the gap list.

## Numbers

- Use only figures the user supplied, in the CV, notes or answers.
- Honest rounding keeps at least two significant figures and goes to the nearest value: 1.27M becomes 1.3M, and 31.4% becomes 31%. A true bound is also fine: 23% becomes "over 20%", and 1.9x becomes "nearly doubled", never "doubled".
- Rounding to a bigger, rounder number is not honest rounding: 23% does not become 25%, $480K does not become $500K, and 3.6x does not become 4x.
- An approximate figure the user hasn't confirmed keeps its marker: `40% [CONFIRM: exact figure]`.
- Don't derive a new metric from the user's figures, such as a percentage from two counts, unless the user agrees with the calculation. Mark it until then.

## Ownership and context

- Team results read as team results: the user's action first, the team's result as context. "Wrote the pricing page for a launch that brought in 1,200 trials in its first month."
- Product or company scale is context, not the user's achievement. "On a delivery app with 500,000 monthly users" is fine; implying the user grew it to that size is not.
- Job titles, employers, dates, degrees and certifications stay exactly as given. Don't move a title up or down to match the posting.
- A headline under the name can name the target role only if it honestly describes the user's work.

## What to cut

- Bullets that neither support a requirement nor show the user's level.
- Objective statements, "references available on request", and soft-skill claims with no evidence: "excellent communicator", "team player", "detail-oriented".
- Skills the user can't back up, or that are out of date for this role.
- Repetition. A result appears once. The summary says who the user is for this job; the bullets carry the proof.

Shorten an older role to title, employer, dates and one line instead of deleting it. If you remove a whole role or section, say so in one line after the CV so the user can restore it.

## Sections and length

- Order: contact details, optional headline, summary, experience, education, skills. Add certifications, projects or languages when the job asks for them.
- Roles stay in reverse chronological order. Reorder the bullets within a role, not the roles.
- Summary: two or three sentences on the user's field, level and the scope of their work, aimed at this job. Exact results belong in the bullets.
- With long experience, an optional Selected results section after the summary can hold the two to four results this job cares about most. Don't repeat them word for word under Experience.
- Skills: an index of what the user has, grouped by type. Not a copy of the posting's requirement list.
- Fit the length by cutting, never by shrinking type or margins. One page is usual early in a career and two with longer experience, unless the user, the posting or local practice says otherwise.
- Write in the posting's language and spelling, US or UK, unless the user prefers otherwise.

## ATS-safe format

Applicant tracking systems read the document's text layer from top to bottom, so keep the layout plain:

- One column. No tables, text boxes, columns, icons, images, charts or skill bars.
- Standard headings: Summary, Experience, Education, Skills.
- Contact details in the body, not in the page header or footer.
- One date format throughout, for example "Mar 2021 – Jun 2024".
- Plain bullets, and a common font once the text is in a document.
- File type: .docx or a PDF with selectable text, unless the posting asks for something else.

## Terms from the posting

For each key term in the posting, decide which case applies:

- **exact and true:** the user has done this under this name. Make sure the term appears as written.
- **same work, different name:** switch to the posting's term, for example "client success" to "customer success".
- **not done:** leave it out of the CV and add it to the gap list.
- **incidental:** ignore it.

Write a term both ways once if the posting does: "search engine optimisation (SEO)". Never repeat a keyword to raise its count, and never hide keywords in white or tiny text.

## Fictional example

Everything below is invented. It shows the method, not facts to reuse.

Before: "Helped with the onboarding redesign, which improved activation by approximately 20%."

The user's answer to one question: "I mapped where trial users dropped off and wrote the new setup checklist. Design and engineering built it. Activation went from 22% to 27% in the first quarter after launch."

After: "Mapped where trial users dropped off and wrote the new setup checklist, built with design and engineering; activation rose from 22% to 27% in the first quarter after launch."

Not allowed: "Led the onboarding redesign, lifting activation by 25%." The user didn't lead it, and 25% overstates the change from 22% to 27%.
